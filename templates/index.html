Finite automata (theory)

Identifier recognition

The automaton starts in q0. A letter or underscore moves it to the accepting state q1, where any number of letters, digits and underscores keep it. A name that begins with a digit never leaves q0, so it is rejected.

Integer recognition

The first digit moves the automaton from q0 to the accepting state q1; further digits stay in q1. The regular expression is [0-9]+.

Theory versus implementation

The diagrams above are theoretical finite automata. LexiScan does not contain a generic DFA engine or a transition table. Its scanner in lexer.py is a hand-written, character-by-character scanner whose loops follow the same states. For example, identifier scanning is:

def scan_identifier(self, line, col):
    start = self.pos
    while is_id_part(self.peek()):   # stay in q1 on letter, digit or _
        self.advance()
    lexeme = self.src[start:self.pos]
    # keyword table lookup decides KEYWORD or IDENTIFIER

The first character is checked in the main loop (is_id_start, which plays the role of the q0 → q1 move). Regular expressions are used in the code only to validate numeric suffixes and character-literal bodies. Operators are matched by trying 3-, 2- and then 1-character candidates, which gives the longest match.

About the Project

Project title

Design and Implementation of a Lexical Analyzer for Source Code Tokenization

Subject: Compiler Design · Academic Year: 2026–2027

Abstract

Lexical analysis is the first phase of a compiler. It converts a stream of characters into a stream of tokens that the parser can use. This project implements a lexical analyzer for a subset of the C language. The scanner reads the source code character by character, identifies lexemes using predefined lexical rules, classifies them into keywords, identifiers, operators, constants, string and character literals, delimiters and comments, and records the line and column of each token. Common lexical errors are detected and reported with their positions, and token statistics are produced. A Flask web application presents the results in tables and charts.

Objectives

  • Scan source code character by character and identify lexemes.
  • Classify lexemes into token categories using longest-match rules.
  • Produce a token table with line and column numbers.
  • Detect lexical errors and report them clearly.
  • Show token statistics and demonstrate regular expressions and finite automata.

Technologies used

  • Python 3 – lexical analyzer (character-by-character scanner)
  • Python re module – validation of numeric suffixes and character literals
  • Flask – web server and JSON API
  • HTML5, CSS3, JavaScript – user interface, charts and CSV export
  • Python unittest – automated tests
